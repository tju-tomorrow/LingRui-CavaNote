## 0. 一句话

**知识资产 = 两类，都注册在知识库：**

- **节点资产**（`KnowledgeNode`）：名词 + 解释（摘要 / 要点 / FAQ / 长文）+ 画布形态
  （形状 / 配色 / 尺寸）+ 关系网（名词的联系）。
- **画布资产**（`CanvasMeta`）：一组已编排好的节点引用 + 布局，标注归属笔记。

用户把资产拖进任意画布直接复用（节点=引用，画布=合并）；Agent 建新节点前先检索
知识库，命中即引用，不重复造名词。**

---

## 1. 为什么（用户诉求 → 设计）

| 诉求 | 落到设计 |
|---|---|
| 知识 = 无数个名词的联系 | 资产 = 名词（`KnowledgeNode`），联系 = `relations`（现有） |
| 知识库定义好了某个节点的解释 | 解释 = `summary` + `roles` + `faq` + 长文（`blockIds`） |
| 定义好就能复用 | 全局唯一 id，N 张画布引用同一资产，各自独立布局 |
| 节点有自己的画布形态 | `meta.shape`（现有）+ 新增 `meta.style`（配色 / 尺寸预设） |
| 可以在知识库修改形态 | 资产详情卡提供形态编辑，画布引用即时生效 |
| 节点像笔记一样 | 长文正文在文档块（`blockIds`），可编辑成篇；资产卡置顶摘要 |
| 直接拖到画布 | 知识库资产浏览器：拖拽 → 画布落点（`addNodesToCanvas`） |
| Agent 按需加载 | 上下文带资产索引 + executor 新增 `loadAsset` / `spawnNode(assetId)` |

## 2. 概念分层（谁拥有什么）

```
知识资产（Y.Doc ROOT_NODES 全局唯一）
   ├─ 解释     summary / roles / faq / tags / 长文正文 blockIds
   ├─ 形态     kind → 形状词汇表 → meta.shape / meta.style 覆盖
   ├─ 关系     relations（到其它资产的边）
   └─ 生命周期 回收站（trash node）→ 所有画布同时失去它

画布（ROOT_CANVASES，引用视图）
   ├─ 选用     nodeIds = 这张画布引用了哪些资产
   ├─ 布局     本画布的 nodeId → position；缺省回落全局 layout
   ├─ 归属     noteId = 画布资产属于哪篇笔记（知识库按此标注）
   └─ 移除     只删引用，资产仍在字典里（其它画布不受影响）

文档（ROOT_NOTES + 块）
   └─ 长文     blockIds → 资产"像笔记一样"的正文（导出以它为准，PRD/知识模型.md §2.1）
```

**画布资产的复用 = 合并**：把源画布的 `nodeIds` + `layout` 整体并进目标画布（或全局
图）。节点引用不复制，位置沿用源布局，边随节点自动出现。</｜DSML｜parameter}, {

**铁律**：资产正文/解释/形态只存在 `ROOT_NODES` 一处；画布与文档只按 id 引用。
拖入画布**不是复制**，是往这张画布的 `nodeIds` 加一个 id + 一个位置。

## 3. 模型改动（极小，全可选，零迁移）

现有字段已覆盖 90% 需求，唯一的显式新增是资产的**画布形态预设**：

```ts
interface KnowledgeNode {
  // —— 现有（复用）——
  title: string;                 // 名词
  summary?: string;              // 一句话解释
  roles?: string[];              // 要点（详情卡 bullets）
  faq?: FaqItem[];               // 相关追问
  tags?: string[];
  blockIds?: string[];           // 长文正文（"像笔记一样"就在这）
  relations: Relation[];         // 名词的联系
  meta?: {
    shape?: string;              // 画布形态 key（形状词汇表 / stencil）
    icon?: string; tech?: string[]; links?: { label: string; href: string }[];

    // —— 新增 ——
    /**
     * 资产级画布形态预设：画布引用统一继承；缺省走 kind → 词汇表默认。
     * 只允许 配色 + 尺寸，不允许 shape 之外的复杂样式（保持词汇表单一职责）。
     */
    style?: { fillColor?: string; strokeColor?: string; size?: [number, number] };
  };
}
```

读链（新增要点）：`buildGraphSpec` 现有 `nodeStyle(kind, meta.shape)` →
改为 `nodeStyle(kind, meta.shape, meta.style)`，一处适配即可全局生效。

## 4. 交互设计

### 4.1 知识库资产浏览器（两类资产，两个 tab）

- **位置**：知识库 Tab 改为资产浏览器，内嵌两个 tab：`节点资产` / `画布资产`。
- **节点资产 tab**：形态缩略（读词汇表）+ `title` + `summary` + 徽标（解释完整度）。
  过滤：Orama 全文搜索（现有）+ `kind` 分组（服务 / 缓存 / 概念 / …）。
- **画布资产 tab**：每张画布一行 —— 标题 + 节点数 + **归属笔记**（`noteId` → 笔记名；
  无归属显示「全局画布」）。按笔记分组。
- **卡片操作**（两类通用）：
  - 拖拽 → 画布：节点资产**引用**（`containerToScene` 落点 → `addNodesToCanvas`）；
    画布资产**合并**（把源画布 `nodeIds` + `layout` 并进当前画布 / 全局图）。
  - 节点点击 → 资产详情（复用 `NodeDetailCard` + 编辑模式，见 §4.3）；
    画布点击 → 打开这张画布（`setActiveCanvas` + 切主区视图）。
  - 右键/更多 → 「加入当前画布」「复制到剪贴板（id / 摘要）」「移入回收站」。

> 画布资产创建时固定写 `noteId`（从当前笔记来），保证「画布属于哪篇笔记」不丢。

### 4.2 拖入画布的两种形态

| 动作 | 结果 |
|---|---|
| 拖入**单个资产** | 画布 +1 引用（本体 + 摆位） |
| 拖入时按住 ⇧ 或开「连同关系」| 资产 + 它的**直接邻居**一起上画布（关系子图，逐步扩散） |

关系子图的扩散规则：以拖入资产为中心，取 `relations` 一跳邻居，最多 N=8 个；
带邻居时同时把边也建上（`connect`）。这体现"知识 = 无数个名词的联系"。

### 4.3 资产详情 = "像笔记一样"可编辑

复用 `NodeDetailCard` 展示（roles / faq 追问已可用），**新增「编辑资产」模式**：

- 名词三件套：`title` / `summary` / `roles`（就地编辑，debounce 写 Y.Doc）。
- FAQ：增删改，空答案保留"点击追问"语义。
- 画布形态：`shape`（词汇表选择器）+ `style`（配色 / 尺寸），改动即预览。
- 关系：列出 `relations`，可删除；新增走画布连线或「指定同类邻居搜索」。
- 长文：跳转/嵌入对应文档块（`blockIds`），正文编辑留在文档视图
  （资产卡只读展示，保证"唯一真相"不被两处编辑）。

## 5. Agent 按需加载机制

> 目标：AI 不再每次凭空新建名词；先查字典，命中就引用。降低重复定义、保持术语一致。

### 5.1 上下文带资产索引（context-packer）

- 对话上下文中注入 `assets: top-k`（k≈12，按「当前画布未引用 + 最近更新 + 搜索相关度」排序）。
- 每条只给轻量签名：`{ id, kind, title, summary, tags, shape }` —— 不展开 roles/FAQ，省 token。
- 语义约束写进 system prompt：**「谈到的名词若已在资产索引，引用它而非新建」**。

### 5.2 executor 新工具

新增一条 `loadAsset`，扩展现有 `spawnNode`（两者配合）：

```ts
// 检索（按需加载第一步）：AI 说出名词，系统在字典里找
loadAsset({ query: string; kinds?: NodeKind[] })
  → { candidates: [{ id, title, summary, tags, shape, relations: [{to, kind, label}] }] }

// 引用（按需加载第二步）：命中资产后把它放进画布
spawnNode({ ..., assetId?: NodeId })   // assetId 存在 → 只加画布引用 + 布局，不写解释
```

- `loadAsset` 检索实现：Orama（现有）+ 精确 id/标题匹配优先。
- `spawnNode(assetId)` 校验：资产必须存在于 `ROOT_NODES`，否则 fallback 新建。
- 关系导入：复习现有 `connect` 工具建立与邻居的边（AI 逐个确认，或随关系子图整组引用）。

### 5.3 兜底与来源标记

- 检索不到 → `spawnNode` 新建资产（`provenance.origin = "ai"`，初稿由 AI 写，人在资产卡
  审改 → `markHuman`）。
- 检索命中但 AI 想改解释 → **不静默改资产**（那是全局的，别的画布都受影响）：
  先引用原资产建边，异议写进新字段前 UI 提示「这会影响其它画布」。
- 回收站语义：资产进回收站后，`loadAsset` 与拖拽都不再命中；恢复后立即回到可复用。

### 5.4 名词一致性（履约检查）

替换检测：会话结束时对比「本会话新建资产数 / 引用的已有资产数」。若引用率 < 阈值
（如 50%）或出现同义词重复（title 相似度 > 0.9），AI 摘要里主动提示用户合并。

## 6. 边界与不变量

1. 资产只在 `ROOT_NODES` 定义一次；任何视图只引用 id。
2. 从画布删除 = 挪出 `nodeIds`；从知识库删除 = 资产进回收站（波及所有画布，UI 需确认）。
3. AI 只能经 executor 改 Y.Doc（沿用可编程护栏，`PRD/知识模型.md` §5.3）。
4. `meta.style` 与 `meta.shape` 都是表现预设，不携带正文语义。
5. 不做 per-canvas 形态覆盖（v1）：形态是资产属性，全画布统一；例外需求后置。
