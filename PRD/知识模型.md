## 0. 一句话

**Knowledge 拥有"知识是什么"，Annotation 拥有"用户画了什么"，二者都是 Y.Doc 一等公民，
都有稳定 id，都能被 AI 按 id 精确引用。** 画布/文档/动画都只是它们的视图。

## 2. 目标模型（to-be）

### 2.1 KnowledgeNode（扩字段，全部 optional）

```ts
interface KnowledgeNode {
  // —— 现有 ——
  id: NodeId;
  kind: NodeKind;
  title: string;
  summary?: string;              // 一句话，画布卡片用
  blockId?: string;              // 主文档块（保留）
  canvas?: CanvasBinding;
  relations: Relation[];
  meta?: {
    icon?: string;               // 节点图标 key（画布）
    tech?: string[];             // 「常见实现」chips，如 ["Nginx","Kong"]
    links?: { label: string; href: string }[];
    [k: string]: unknown;
  };

  // —— 新增 ——
  roles?: string[];              // 「核心作用」要点，详情卡 bullets
  faq?: FaqItem[];               // 「相关知识」问题（详情卡可点追问）
  tags?: string[];
  blockIds?: string[];           // 一个节点可跨多个文档块（blockId 为兼容保留）
  chapterId?: ChapterId;         // 归属章节 / 分镜
  provenance?: Provenance;       // 来源标记（见 §2.4）
}

interface FaqItem {
  id: string;
  q: string;                     // 问题
  a?: string;                    // 答案（可空：点击时让 AI 现场回答）
}

/** 长文与短要点的分工：
 *  - roles  = 详情卡的短要点（结构化，AI 可增量改）
 *  - 文档块（blockIds 指向）= 长文正文，**导出以它为准**
 *  两者同源：AI 生成/更新时同时维护，不重复（幂等 upsert，见 PRD/主界面.md §5.3）。
 */
```

### 2.2 Chapter（章节 / 分镜）

```ts
interface Chapter {
  id: ChapterId;
  title: string;                 // 如「请求进入网关」
  order: number;
  startT?: number;               // 时间轴起始秒（分镜缩略图点击定位用）
}
```

> `Chapter` 是 `Node.chapterId` 的分组目标；时间轴的分镜缩略图直接读它。

### 2.3 Annotation（手绘 / 便签 / 注释 —— 新增一等公民）

```ts
type AnnotationId = string;
type AnnotationType = "draw" | "sticky" | "text" | "highlight" | "arrow" | "shape";

interface Annotation {
  id: AnnotationId;
  type: AnnotationType;
  /** 挂到某个节点；省略 = 自由注释（不隶属任何知识节点） */
  attachedTo?: NodeId;
  /** 最小几何 + 样式（Excalidraw 元素子集），序列化持久化 */
  element: AnnotationElement;
  /** 便签/文本内容，单独存便于 AI 引用与 Orama 搜索 */
  text?: string;
  provenance: Provenance;
}

interface AnnotationElement {
  type: AnnotationType;
  x: number; y: number; width: number; height: number;
  angle?: number;
  points?: ReadonlyArray<readonly [number, number]>;  // draw / arrow
  strokeColor?: string; backgroundColor?: string; fillStyle?: string;
  roughness?: number; roundness?: unknown;
  /** Excalidraw 原始 seed/version，保证渲染一致性 */
  seed?: number; version?: number;
}
```

**为什么要 `attachedTo` + `text` 单列**：AI 要靠 id 精确引用（"把这个便签挪到网关右边"
"删掉我圈的这块"）。只存裸 Excalidraw 元素做不到。

### 2.4 Provenance（来源标记）

```ts
interface Provenance {
  origin: "ai" | "human";
  /** 自上次 AI 交互以来，人是否改过（供 Context Packer 生成增量上下文） */
  dirty?: boolean;
  /** 最后改动时间戳（毫秒） */
  at?: number;
}
```

> ✅ **已落地**（另一 session，`packages/knowledge/src/schema.ts`）：
> `markHuman(doc,id)` / `markAi(doc,id)` / `isHumanOwned(node)`。
> `updatedBy`（协同最后修改者）留待协同阶段。

### 2.5 NodeProgress（学习进度，per-user）

```ts
type ProgressState = "todo" | "learning" | "done";

interface NodeProgress {
  state: ProgressState;
  updatedAt: number;
}

/** 进度是"每个人自己的"，**不能**放在共享 node 上（协同下会互相覆盖）。
 *  Y.Doc 根：ROOT_PROGRESS = "progress"，形状 { [userId]: { [nodeId]: NodeProgress } }。
 *  单机（无协同）时 userId = "local"。 */
```

## 3. Y.Doc Schema（新增 roots）

| Root | 类型 | 说明 |
|---|---|---|
| `meta` | `Y.Map<KnowledgeDocMeta>` | 现有 |
| `nodes` | `Y.Map<KnowledgeNode>` | 现有 |
| `order` | `Y.Array<NodeId>` | 现有 |
| `layout` | `Y.Map<NodePosition>` | 现有 |
| **`annotations`** | `Y.Map<Annotation>` | **新增**，手绘/便签 |
| **`chapters`** | `Y.Array<Chapter>` | **新增**，章节/分镜 |
| **`progress`** | `Y.Map<Record<userId, Record<NodeId, NodeProgress>>>` | **新增**，per-user |

### CRDT 取舍

- `KnowledgeNode` 仍以**整 JSON 对象**存在 `Y.Map`（P0 现状）：并发改同一节点是整对象 LWW。
  P1.6 保持，字段级拆分留到后续。
- `Annotation` **一元素一条** Y.Map entry（key = annotationId），元素级 LWW。
  手绘会产生大量独立元素，元素级 LWW 足够；同一元素并发编辑极罕见。
- `progress` 按 `userId` 分桶，天然避免多人互相覆盖。

## 4. CanvasSnapshot（喂给 AI 的上下文格式）

Context Packer 产出的结构化数据（与截图**同版本冻结**）：

```ts
interface CanvasSnapshot {
  version: number;                 // 单调递增；与截图对齐的版本号
  viewport: { scrollX: number; scrollY: number; zoom: number; width: number; height: number };
  nodes: Array<{
    id: NodeId; kind: NodeKind; title: string; summary?: string; roles?: string[];
    at: [number, number]; size: [number, number];
    provenance?: Provenance;
  }>;
  relations: Array<{ from: NodeId; to: NodeId; kind: RelationKind; label?: string }>;
  annotations: Array<{
    id: AnnotationId; type: AnnotationType; text?: string;
    bbox: [number, number, number, number];   // x,y,w,h —— 让 AI 把像素↔id 对上
    attachedTo?: NodeId; provenance: Provenance;
  }>;
  chapters: Chapter[];
  focus?: NodeId;
  // selection 默认不发（避免干扰模型），需要时再开
}
```

> **同一格式既作喂 AI 的导出，也作持久化读取**（单一格式，避免两套）。
> 版本号 `version` 用于保证"截图与数据同一时刻"。

## 5. 不变量

1. `NodeId` / `AnnotationId` 全局唯一，任何视图改名前先解析到它。
2. 画布/文档/动画**只持有 id**，不存正文；正文在 Y.Doc。
3. **AI 只能通过 `executor` 改 Y.Doc**（见另一 session 的 `packages/ai/src/executor.ts`）。
4. 新增字段全部可选 → 旧数据零迁移。
5. 导出以**文档块正文**为准（`blockIds`），`roles` 是卡片投影。
