## 0. 一句话

让用户用 AI + 本项目的工具，**养一只属于自己的宠物**；这只宠物在知识动画里充当**老师**，
把链路讲给用户听，并可导出成教学视频。

---

## 1. 关键区分：讲解宠 ≠ 监工宠（本产品的差异点）

现有生态几乎都是"**监工宠**"：盯着 AI agent 在干嘛，向用户汇报状态。我们要的是"**讲解宠**"：
盯的是**用户**（学生），把知识讲给用户听。

| | 监工宠（Clawd / AgentPet…） | **讲解宠（本产品）** |
|---|---|---|
| 关注对象 | AI agent 的运行状态 | 用户的理解进度 |
| 数据源 | 编码 agent 的 hooks / 事件 | Knowledge / `SceneScript` |
| 输出 | 状态动画 + 通知 | 讲解旁白 + 画布演出 |
| 落盘 | 无 | **导出教学视频** |
| 归属 | 工具 / 项目 | **"我的"宠物**（Personal） |

---

## 2. 与现有 mascot 的关系（泛化，不是新增）

`packages/mascot` 的 VRM 吉祥物 = "**一个固定宠物**"。Personal Pet 把它**泛化**：

- 宠物 = 可定制、可拥有的资产；**VRM 只是其中一种形态**。
- 默认宠物仍叫 **LingRui**；用户可自定义名字 / 外观 / 口吻。
- → **VRM 形态需补**：像素形态升为**并列一等公民**（见 §4）。

---

## 3. PetSpec（宠物模型）

```ts
type PetId = string;
type PetForm = "pixel" | "vrm" | "ascii";

interface PetSpec {
  id: PetId;
  name: string;                                   // "灵睿" / 用户起的名
  form: PetForm;
  palette: string[];                              // 像素形态主色
  states: Partial<Record<PetState, SpriteSet | ClipRef>>;
  personality: { tone: "friendly" | "rigorous" | "funny" | string; lang?: string };
  voice?: { tts?: string; pitch?: number; speed?: number };
  ownerId?: string;                               // per-user
  provenance: Provenance;                          // 见 PRD/知识模型.md §2.4
  source?: { gallery?: string; format?: "codex-sprite" | "native" };  // 导入来源
}

interface SpriteSet { sheet: string; frames: number; fps: number; }  // 精灵图
interface ClipRef { asset: string; }                                 // VRM 动画引用
```

## 4. 形态

| 形态 | 定位 | 理由 |
|---|---|---|
| **像素（首选）** | 默认形态 | 轻量、sprite 状态驱动、与 Revideo 视频导出天然契合、可调色板换皮（参考 Clawd 的 3 主题） |
| VRM | 高级形态 | 3D 表现力强，但资产重、导出慢 |
| ASCII（可选） | 极简 / 终端 | 参考 Campy |

**推荐：像素优先，VRM 后置**（不否定 VRM，只是不再唯一）。

---

## 5. 教学状态机（PetState）

在现有 `idle / run / talk / point / think` 之上，按"老师"语义扩：

```
idle      待机
think     思考
explain   讲解中（对应 talk）
point     指向某个节点
run       移动到下一站
celebrate 讲完一段
confused  被追问 / 没听懂
sleep     长时间空闲
```

每个状态映射到像素帧组或 VRM clip。**与 Clawd 的状态词汇做兼容映射**（便于导入它的主题）。

## 6. AI 用本项目的工具构建宠物（PET_TOOLS）

扩 `@lingrui/ai`，与 `CANVAS_TOOLS` 同构（AI 通过 executor 落到 Y.Doc）：

```
createPet(spec)          新建宠物（名/形态/调色板）
setPetAppearance(id,...) 改外观 / 换皮 / 改名
setPetPersonality(id,...) 口吻 / 语言
setPetState(id, state, sprite)  上传/生成某状态动画
importPet(url | format)  从画廊 / Codex sprite 导入
deletePet(id)
```

**AI 生成流程**：

```
用户："给我一只蓝色的猫老师"
  → createPet({ name:"猫老师", form:"pixel", palette:["#5b8def",…] })
  → setPetState(...) 生成/挑选各状态精灵
  → 存 ROOT_PET（Y.Doc）
  → 成为"我的宠物"，之后所有讲解由它出演
```

资产来源（**待确认**，建议组合）：参数化模板（最省、可换皮）→ 画廊导入 → 图像生成（后期）。

## 7. 在动画里当老师（SceneScript 泛化）

现有 `mascot.moveTo` / `mascot.say` **泛化为 `pet.*`**（`mascot.*` 保留为别名，向后兼容）：

```ts
| { t; kind: "pet.moveTo"; nodeId: string; state?: PetState }
| { t; kind: "pet.say";    text: string; nodeId?: string }
| { t; kind: "pet.teach";  nodeId: string; text: string; state?: "explain" }  // 走到+讲解+旁白
| { t; kind: "pet.react";  to: "confused" | "aha" | "celebrate" }
```

`pet.teach` 一条动作完成"老师走到节点 → 讲解 → 旁白"，是讲解场景的基本单位。
与 `PRD/演出层.md` 的时间轴 / seek / 分镜 / 进度全部复用。

## 8. 导出「Personal Pet 教学视频」

复用 P4 的两条渲染通道（`PRD/导出与分发.md`）：同一 `SceneScript` → Revideo 离线渲染。
产物 = **你的宠物当老师讲完一个知识点的视频**。桌面端在 main 进程跑。

这也是产品 slogan 的落地：

> **"让 AI 用本项目工具养一只老师宠物，把你的知识链路演给你听，并导成视频。"**

## 9. 互操作（增长点）

- **导入** Codex sprite format / Petdex 宠物 → 立刻拥有海量皮肤。
- **导出**我们的 pet 到该格式 → 反向分发。
- 复用 Clawd 的状态词汇做兼容映射。

## 10. 存储

- `ROOT_PET`（Y.Doc）：`PetSpec` + 当前选中宠物 id。
- **宠物是 per-user 的**（"我的"），多协同时不共享 → 同 `progress` 分桶思路
  （见 `PRD/知识模型.md` §2.5）。
- 大资产（精灵图 / VRM）放 S3/MinIO，Y.Doc 只存引用。
