## 0. 背景

用户要的是**桌面端**。它不是另做一个 app，而是把「主界面」装进一个本地容器：
离线可用、能读写本地文件、能离线导出视频、能安全持有 LLM Key。

---

## 1. 选型决策：**选 Electron**

| 维度 | Electron | Tauri | 本项目权重 |
|---|---|---|---|
| **渲染一致性** | 自带 Chromium，跨平台一致 | 系统 webview（WKWebView / WebView2 / WebKitGTK），有差异 | ⭐⭐⭐ 高 |
| **Node 运行时** | 主进程原生 Node | 需 sidecar（另打包 Node/Bun）或 Rust 重写 | ⭐⭐⭐ 高 |
| **离线能力** | 直接内嵌服务 | 依赖 sidecar | ⭐⭐⭐ 高 |
| 产物体积 | ~80–150MB | ~3–10MB | ⭐ 低 |
| 内存占用 | 高 | 低 | ⭐⭐ 中 |
| 启动速度 | 中 | 快 | ⭐ 低 |
| 安全默认 | 需自行加固 | 默认较好 | ⭐⭐ 中 |
| 语言/团队 | 全 TS/Node（现状） | 引入 Rust | ⭐⭐⭐ 高 |
| 生态成熟度 | 成熟 | 成长中 | ⭐⭐ 中 |
| License | MIT | MIT / Apache-2.0 | 等价 |

**结论：Electron。** 理由按权重排序：

1. **渲染一致性护住地基**：本项目是图形重度应用——Excalidraw（SVG/DOM）、PixiJS（WebGL）、
   three-vrm（WebGL）、BlockNote（ProseMirror）。Chromium 一致能避免一整类「某平台画不出来 /
   WebGL 行为不同 / OffscreenCanvas 缺失」的坑。Tauri 的系统 webview 差异会把画布/VRM 变成
   平台适配泥潭。
2. **主进程 Node 直接承载本地服务**：内嵌 Hocuspocus 协同、`/api/chat` LLM 代理、Revideo 离线
   视频导出、PGlite/文件访问——全部留在 Node，不用 sidecar，不引入 Rust。
3. **全 TS，零新增语言**：与现有 monorepo 一致。

> **何时才选 Tauri**：若「体积/内存」成为硬指标，且团队接受 Rust + 系统 webview 差异，
> 并愿意把协同服务/导出做成 sidecar。当前不满足。

## 2. 架构

```
apps/desktop/                     Electron + electron-vite
├─ main/        (Node 主进程，唯一有权限的地方)
│   ├─ collab-server   内嵌 Hocuspocus，仅绑 127.0.0.1 + 随机端口 + token
│   ├─ chat-proxy      /api/chat（搬 apps/collab 逻辑；LLM Key 只在此）
│   ├─ exporter        Revideo 离线渲染 → MP4/WebM
│   └─ fs             读写本地 .lingrui / 导出文档 PDF·MD
├─ preload/     contextBridge 暴露最小 IPC API
└─ renderer/    复用 apps/web 的 Vite 产物（不 fork）
```

**复用策略**：不 fork `apps/web`。通过环境/平台检测切换后端：
- Web 版：连远端 `VITE_COLLAB_URL` / 远端 `/api/chat`。
- 桌面版：连 `127.0.0.1` 内嵌服务。

同一份前端代码，两个后端目标。

---

## 3. 安全边界

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- **LLM API Key 只存在 main 进程**，renderer 永不接触（这也顺带解决了 web 版把 Key 暴露给
  浏览器的问题）。
- 本地服务只绑 `127.0.0.1`，带一次性 token，端口随机。

---

## 4. 打包与分发

- 构建：`electron-vite`；打包：`electron-builder`。
- 目标：macOS（dmg + 公证）、Windows（nsis）、Linux（AppImage/deb）。
- 自动更新：`electron-updater` + 静态托管（S3/MinIO）。
- 签名：Apple Developer ID 公证 + Windows 代码签名。

---

## 5. 时机（不动现有分期）

桌面端是**交付形态**，不改变 P0–P4 的功能分期。建议节奏：

> 先在浏览器里把 **P3（真实 LLM + 工具调用 + 共编闭环）** 跑通，再套 Electron 壳。
> 过早包壳会把「跨进程调试」和「功能未定」两件事叠在一起。

`packages/knowledge/src/schema.ts`、`packages/canvas/src/*`、`bun.lock`。

因此本桌面端落地时必须**串行**：

2. 编码阶段：新增 `apps/desktop/`。注意根 workspace 是 `apps/*` 通配，
   新建 `apps/desktop/package.json` 会让**下一次 `bun install`** 改变 `bun.lock`——
   必须与另一 session 的安装**错开**，或由同一 session 收尾。
3. 收尾：才改根 `package.json`（scripts）与 `bun.lock`。
